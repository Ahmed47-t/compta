# دليل الإصدارات وبوابة الإطلاق (RELEASE.md)

**المشروع:** PC COMPTA Next (`Ahmed47-t/compta`)  
**الإصدار:** 1.0 — يوليو 2026  
**الهدف:** تحديد معايير وسياسات إدارة الإصدارات (`Versioning Strategy`)، وبروتوكولات بناء الحزم الموقعة لـ Windows، ومتطلبات بوابة الإطلاق (`Go / No-Go Gate`).

---

## 1. سياسة التسمية والإصدار (`Versioning & Channels Policy`)

يعتمد المشروع سياسة ترقيم تجمع بين **الترقيم الدلالي (`Semantic Versioning SemVer: MAJOR.MINOR.PATCH`)** والإشارة لتاريخ التقويم المحاسبي:
- `MAJOR` (مثلاً `1.x.x`): تغييرات جوهرية أو تحديث شامل لهيكل الجداول (`Alembic Major Schema Break`) يتطلب هجرة كبرى.
- `MINOR` (مثلاً `1.1.x`): إضافة ميزات محاسبية أو تقارير جبائية جديدة متوافقة مع القوالب الحالية دون كسر البيانات السابقة.
- `PATCH` (مثلاً `1.1.1`): إصلاحات أخطاء سريعة أو تحسينات في سرعة شبكة الإدخال (`Saisie Grid`).

### قنوات الإصدار (`Release Channels`):
1. **قناة التطوير الداخلية (`Alpha / Nightly`):** مخصصة للاختبارات الآلية وفحص محركات الباك اند.
2. **قناة التجريب المحدود (`Beta / Pilot`):** مخصصة للمكاتب المحاسبية الخمسة المشاركة في المرحلة 12 الميدانية (`Pilot Program`).
3. **قناة الإطلاق الرسمي (`Stable / General Availability`):** الإصدارات المعتمدة والممهورة بتوقيع الأمان والامتثال الضريبي.

## 2. خطوات بناء وتوقيع حزمة تثبيت Windows (`Building & Signing Windows Installer`)

يتم إعداد وبناء الحزمة التلقائية لسطح المكتب باستخدام أداة `Tauri Bundler` وحزمة `NSIS` المدمجة مع محرك Python و PostgreSQL الصامت:

```bash
# 1. إعداد وتثبيت إصدار النواة المحاسبية وخدمة OCR في مجلد البناء
cd tools/builder
python build_fastapi_bundle.py --target-os windows

# 2. بناء حزمة سطح المكتب Rust Tauri لـ Windows 64-bit
cd ../../apps/desktop
cargo tauri build --target x86_64-pc-windows-msvc
```

### التوقيع الرقمي للحزمة (`Authenticode & Checksums`):
- يحظر إطلاق أي حزمة تنفيذية (`.exe` أو `.msi`) دون توقيعها بشهادة توقيع الرمز الرقمية الرسمية (`Code Signing Certificate`) لمنع تنبيهات Windows Defender وحماية المكاتب من العبث بالمثبت.
- يتم توليد ملف `SHA-256 Checksum` للحزمة النهائية ونشره مع ملاحظات الإصدار (`Release Notes`).

## 3. بوابة الإطلاق واجتماع الاعتماد (`Go / No-Go Release Gate`)

قبل نشر أي إصدار في قناة `Beta` أو `Stable`، يجب أن تجتمع لجنة الإطلاق (أو يتم إجراء التحقق المنهجي الآلي الشامل) لضمان تحقق شروط بوابة الإطلاق الصارمة:

### قائمة التحقق الإلزامية للإطلاق (`Release Gate Checklist`):
- [ ] **صفر أخطاء حرجة (`No Open Sev-1/Critical Bugs`):** عدم وجود أي خطأ يؤثر على التوازن المحاسبي أو يتسبب بانهيار شاشة السaisie.
- [ ] **نجاح 100% لاختبارات الهجرة والاسترجاع:** نجاح اختبار استيراد عينة `DLG` الذهبية واختبار استعادة حزمة احتياطية مشفرة على بيئة نظيفة.
- [ ] **تحقق التغطية ومصفوفة التتبع:** تأكيد أن كل متطلب حرج في `TRACEABILITY_MATRIX.md` يحمل الحالة `Completed` واجتاز خط الـ CI.
- [ ] **التحقق من الأختام الجبائية:** فحص عمل خوارزمية التوقيع `RSA` عند إغلاق السنة المالية دون أخطاء.
- [ ] **موافقة الخبراء:** توقيع خبير النظام المحاسبي (`SCF Domain Lead`) ومهندس الأمان (`Security Lead`).

> **قرار الرفض (`NO-GO`):** في حال عدم تحقق أي من الشروط المذكورة أعلاه، يتم إلغاء الإطلاق وإصدار تقرير `NO-GO` صريح، ويتم توجيه جميع المطورين والوكلاء لمعالجة العائق حصرياً.
