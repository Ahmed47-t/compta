# مواصفات المرحلة 04: قاعدة البيانات والمعاملات والتدقيق (PHASE-04.md)

**المرحلة:** Phase 04  
**الخبير المطلوب:** Principal PostgreSQL Engineer + Application Security Engineer  
**الهدف الأساسي:** تصميم وتنفيذ طبقة التخزين الدائمة (`Persistence & Database Layer`) في PostgreSQL 16 بناءً على نموذج المجال (`Domain Model`) مع تطبيق المعاملات الآمنة، وسجل التدقيق المقاوم للحذف (`WORM Audit Log`)، وسلسلة التجزئة (`Hash Chain`).

---

## 1. نطاق العمل المطلوب (Scope of Work)

1. **تصميم المخطط والمهاجرات (`PostgreSQL Schema & Alembic`):** تصميم الجداول الـ 15 المعتمدة في المخطط الرئيسي (`MASTER_PLAN.md`) انطلاقاً من طبقة المجال، مع تقسيم الجداول حسب السنة المالية (`Partitioning by Exercice`).
2. **الأنواع والقيود الميكانيكية (`Data Types & Constraints`):** فرض النوع `NUMERIC(19,2)` لكل المبالغ المالية، وبناء قيود قاعدة بيانات (`CHECK / TRIGGER Constraints`) كخط دفاع ثانٍ يمنع إدراج قيود غير متوازنة في الفوليو المغلق.
3. **المعاملات والتزامن (`Transactions & Concurrency`):** ضبط حدود المعاملات الذرية (`ACID Transactions`)، والتحكم في التزامن المتفائل/المتشائم (`Optimistic Concurrency Controls`) وضمان عدم تكرار تنفيذ العمليات (`Idempotency`).
4. **نظام التحكم بالوصول وتقييد الصفوف (`RBAC & RLS`):** إنشاء الأدوار والصلاحيات (5 أدوار بالـ `RBAC`)، وتفعيل `Row-Level Security (RLS)` مع سياسة الرفض التلقائي (`Deny-by-default`).
5. **سجل التدقيق المقاوم للحذف (`WORM Append-Only Audit`):** بناء جدول `audit_logs` بصلاحيات إدراج فقط (`Append-Only`) مع تفعيل إضافة التدقيق `pgaudit` وسلسلة التجزئة للسطور (`prev_hash, curr_hash`).
6. **سلسلة التجزئة وأختام الإغلاق (`Folio Hashes & Seals`):** تنفيذ جداول ومحركات حساب تجزئة القيود والأختام الجبائية المشفرة (`exercice_seals`).
7. **استراتيجية التراجع والترقية (`Upgrade / Downgrade Migrations`):** إعداد نصوص مهاجرة عكسية آمنة لا تؤدي إلى محو أو إتلاف البيانات المحاسبية المعتمدة.
8. **اختبارات التكامل والأداء تحت الضغط (`Stress Testing`):** توليد بيانات اصطناعية لـ 500,000 سطر واختبار سرعة استعلامات ميزان المراجعة باستخدام `EXPLAIN ANALYZE` والتحقق من التزامن وفشل منتصف المعاملة.

---

## 2. بوابة القبول (Acceptance Gate)

- نجاح اختبارات التزامن والمعاملات الذرية (`ACID Integration & Concurrency Tests`).
- استحالة تعديل أو حذف أي قيد معتمد من قاعدة البيانات حتى في حال محاولة تجاوز التطبيق ومهاجمة SQL مباشرة في ظل تطبيق سياسات `RLS`.
- سجل التدقيق يسجل كل عملية حساسة دون تسريب أسرار أو بيانات شخصية (`PII-free`).
- مهاجرة قاعدة البيانات تعمل بسلاسة وسرعة من قاعدة فارغة ومن نسختها السابقة.
