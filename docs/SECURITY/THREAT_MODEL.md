# نموذج التهديدات وتحليل المخاطر الأمنية (THREAT_MODEL.md)

**المشروع:** PC COMPTA Next (`Ahmed47-t/compta`)  
**الإصدار:** 1.0 — يوليو 2026  
**المنهجية المعتمدة:** تحليل التهديدات وفق إطار **STRIDE** (`Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege`) المخصص لتطبيقات سطح المكتب المالية والمحاسبية الحساسة (`Desktop Monolith / Local API / Partitioned DB`).

---

## 1. سطح الهجوم وحدود الثقة (Attack Surface & Trust Boundaries)

ينقسم النظام إلى 4 حدود ثقة حرجة (`Trust Boundaries`):
1. **حد واجهة سطح المكتب (`TB-01: UI <-> IPC / Local API`):** الاتصال بين تطبيق Tauri (Rust WebView) وخدمة FastAPI الخلفية عبر قناة محلية (`localhost / IPC Pipe`).
2. **حد قاعدة البيانات (`TB-02: API <-> PostgreSQL`):** الاتصال بين خدمة FastAPI وقاعدة بيانات PostgreSQL 16 المحلية أو المستضافة على سيرفر المكتب.
3. **حد معالج الـ OCR واستقبال الملفات (`TB-03: UI <-> OCR Worker`):** استقبال ملفات PDF والصور الخارجية من الموردين لمعالجتها في خدمة بايثون المحلية.
4. **حد النسخ الاحتياطي ونظام الملفات (`TB-04: File System <-> Backups/DLG`):** التفاعل مع مجلدات تخزين النسخ الاحتياطية وملفات قاعدة البيانات القديمة (`.DLG`).

---

## 2. مصفوفة التهديدات وسيناريوهات الهجوم (STRIDE Threat Matrix)

### 2.1 انتحال الهوية (`Spoofing`)
- **التهديد:** محاولة برنامج خبيث على حاسوب المحاسب انتحال واجهة Tauri أو استدعاء نقاط اتصال `FastAPI` مباشرة عبر `localhost` لإدراج قيود أو سحب بيانات الشركات.
- **التخفيف وإجراءات الحماية:**
  - تطبيق مصادقة محلية متبادلة (`Local Secret Token / IPC Mutual Auth`) يُولد عشوائياً عند تشغيل النواة ويتم تمريره حصرياً في ذاكرة عملية Tauri المحمية.
  - تقييد استماع خادم FastAPI على حلقة العودة المحلية (`127.0.0.1` فقط في الإصدار المنفرد) ومنع الاتصالات الخارجية غير الموثقة في إعدادات `pg_hba.conf`.

### 2.2 التلاعب والتزوير (`Tampering`)
- **التهديد:** قيام مستخدم داخلي (أو مهاجم تمكن من الوصول لنظام الملفات) بتعديل أرقام القيود المعتمدة في قاعدة البيانات مباشرة عبر `pgAdmin` أو `SQL Injection` أو التلاعب بملفات النسخ الاحتياطي.
- **التخفيف وإجراءات الحماية:**
  - **حماية القيود (RLS):** تفعيل تقييد الوصول على مستوى الصفوف (`Row-Level Security`) في PostgreSQL؛ حيث تُمنع أوامر `UPDATE / DELETE` على جدول `pcc_glv` للقيود بحالة `POSTED`.
  - **سلسلة التجزئة (`Hash Chain`):** كل قيد وكل فوليو يحتفظ بحقل `prev_hash` و `curr_hash`. أي تعديل في سطر قديم سيؤدي لكسر السلسلة واكتشاف التزوير فوراً.
  - **أختام السنة المالية (`RSA Seals`):** توقيع الإغلاق النهائي لميزان السنة المالية بمفتاح غير متماثل `RSA Signature`.
  - **التحقق المدخلات:** استخدام `Pydantic v2 Strict Validation` وأمر `SQLAlchemy Core Parameterized Queries` لمنع حقن SQL نهائياً.

### 2.3 الإنكار (`Repudiation`)
- **التهديد:** إنكار مستخدم أو محاسب إجراء تعديل أو قيد عكسي على حساب أو فاتورة حساسة.
- **التخفيف وإجراءات الحماية:**
  - **سجل التدقيق غير القابل للمحو (`WORM Audit Log`):** كل عملية إدخال أو تعديل أو تصحيح تُسجل إجبارياً في جدول `audit_logs` بصلاحية إدراج فقط (`Append-Only`).
  - تسجيل هوية المستخدم، ومعرّف الشركة، والتاريخ الدقيق، والقيمة السابقة والجديدة (`JSONB Diff`)، وعنوان IP و UUID للجهاز، وتجزئة السجل نفسه لضمان عدم حذفه أو تعديله.

### 2.4 إفشاء المعلومات (`Information Disclosure`)
- **التهديد:** تسرب أرصدة وبيانات الشركات المالية وحسابات العملاء والموردين في حال سرقة الحاسوب المحمول للمحاسب أو تسريب ملف النسخة الاحتياطية.
- **التخفيف وإجراءات الحماية:**
  - تشفير قاعدة البيانات في حالة الراحة (`At-Rest Encryption بـ AES-256 / pgcrypto`).
  - تشفير جميع ملفات النسخ الاحتياطية بكلمات مرور قوية وحفظ المفاتيح في خزانة أسرار نظام التشغيل (`Windows Credential Manager / Keychain`).
  - حجب وتطهير أي أسرار أو أرقام مالية في سجلات الخطأ (`Structured PII-Free Logs`).

### 2.5 حجب الخدمة (`Denial of Service - DoS`)
- **التهديد:** سحب وإفلات ملفات PDF عملاقة وملغمة في واجهة الـ OCR تؤدي لاستهلاك الذاكرة الكامل (`RAM Exhaustion`) وتجمد حاسوب المكتب.
- **التخفيف وإجراءات الحماية:**
  - فرض حدود قصوى لأحجام الملفات (`Max File Size <= 15MB`) وتحديد مهلة قصوى للمعالجة (`Timeout = 30s per page`).
  - عزل معالج الـ OCR في عملية منفصلة (`Separate Process / Async Job Queue`) مع قاطع دورة (`Circuit Breaker`) يمنع تعطل النواة المحاسبية أو شاشة الإدخال في حال فشل أو تجمد استخراج الصورة.

### 2.6 تصعيد الصلاحيات (`Elevation of Privilege`)
- **التهديد:** محاولة محاسب إدخال (`Comptable-Saisie`) ترقية صلاحياته للوصول لإعدادات الشركة أو إغلاق السنوات أو قراءة موازين المراجعة العامة غير المسموح له بها.
- **التخفيف وإجراءات الحماية:**
  - تطبيق التحكم بالوصول المبني على الأدوار (`RBAC`) مع 5 أدوار صارمة، وتمرير دور المستخدم وحالة جلسة العمل في كل استدعاء لقاعدة البيانات ليتم الفحص الميكانيكي على مستوى `RLS Policy`.
