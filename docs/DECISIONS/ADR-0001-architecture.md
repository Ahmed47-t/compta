# ADR-0001: المعمارية العامة للمشروع ومكدس التطوير (Tech Stack & Architecture)

**تاريخ القرار:** 2026-07-16  
**الحالة:** المعتمد (`Accepted`)  
**أصحاب المصلحة:** Principal Software Architect, Technical Program Manager, Principal Desktop & Database Engineers  

---

## 1. السياق والمشكلة (Context & Problem Statement)

يستهدف مشروع **PC COMPTA Next** استبدال النظام المحاسبي التاريخي المهيمن في مكاتب المحاسبة الجزائرية (`DLG PC COMPTA`). على الرغم من قدم النظام الأصلي (واجهات Win32 وقواعد بيانات BDE/dBASE قديمة غير مشفرة)، إلا أنه يتمتع بميزتين حاسمتين تجعلان المحاسبين متمسكين به: **السرعة اللحظية في الاستجابة وإدخال اليوميات باستخدام الكيبورد، والاستقلالية التامة في العمل المحلي (`100% Offline`)**.

التحدي المعماري هو بناء نظام حديث يوفر:
1. نفس سرعة أو تفوق سرعة Delphi الأصلي (استجابة `< 50ms` لبحث الحسابات و `< 300ms` لفتح موازين المراجعة الضخمة التي تتجاوز 500,000 قيد).
2. تشفير وأمان بنكي مدمج (`AES-256`, `RLS`, `WORM Audit Logs`, `Hash Chain`).
3. محرك ذكاء اصطناعي محلي لاستخراج وثائق وفواتير الموردين (`Offline OCR Factory`).
4. التوافق والتشغيل السلس على أجهزة الحواسيب المكتبية المتوسطة والضعيفة (`e.g., Core i3 4th Gen, 4GB RAM, Windows 10/11`) المنتشرة في مكاتب المحاسبة.

## 2. الخيارات المتاحة والمدروسة (Considered Options)

### الخيار الأول: تطبيق سحابي كامل (`Cloud-Native Web SaaS Application`)
- **الوصف:** بناء النظام كمنصة ويب (React/Next.js) تتصل بخوادم سحابية وقاعدة بيانات PostgreSQL سحابية ومحرك OCR سحابي.
- **المزايا (`Pros`):** سهولة التحديث المركزي، الوصول من أي مكان، عدم الحاجة لتثبيت أي برامج على جهاز العميل.
- **العيوب (`Cons`):**
  - مرفوض من قبل معظم مكاتب المحاسبة الجزائرية بسبب مخاوف سرية وخصوصية البيانات المالية للعملاء.
  - التبعية المطلقة للإنترنت؛ أي انقطاع يعطل المكتب بالكامل.
  - تأخير الشبكة (`Network Latency`) يدمر تجربة إدخال اليومية السريعة بالكيبورد (`Keyboard-First Saisie`).

### الخيار الثاني: تطبيق Electron مع قاعدة بيانات SQLite محمية (`Electron + Node.js API + SQLCipher`)
- **الوصف:** تطبيق سطح مكتب شامل باستخدام Electron وقاعدة بيانات ملفات محمية (`SQLCipher/SQLite`).
- **المزايا (`Pros`):** عمل محلي كامل (`Offline`) وسهولة التطوير عبر تقنيات جافاسكريبت.
- **العيوب (`Cons`):**
  - استهلاك مفرط للذاكرة (`Electron RAM Overhead > 500MB - 1GB`) مما يؤدي لبطء شديد وتجمد على أجهزة الحواسيب الضعيفة (4GB RAM).
  - محدودية SQLite في التعامل مع المعاملات المتزامنة (`Concurrency`) وموازين المراجعة الضخمة للسنوات المتعددة في المكاتب الكبرى، وافتقارها لآليات الأمان الصارمة مثل `RLS` و `Audit WORM Triggers`.

### الخيار الثالث: معمارية مدمجة مقسمة للمحركات (`Tauri Rust + React/TS + Python FastAPI + PostgreSQL 16 Partitioned + Local OCR Worker`)
- **الوصف:** تطبيق سطح مكتب خفيف باستخدام `Tauri 2.x` المتصل بخدمة خلفية محلية (`Python FastAPI Modular Monolith 9 Engines`) تعمل فوق قاعدة بيانات `PostgreSQL 16 Partitioned` ومحرك استخراج وثائق محلي مستقل `Python OCR Worker`.
- **المزايا (`Pros`):**
  - **خفة وسرعة خارقة:** Tauri يستهلك ذاكرة أقل بنسبة 90% من Electron (حوالي `30-50MB RAM`) ويحاكي سرعة تطبيقات الأصلية.
  - **قوة قاعدة البيانات:** `PostgreSQL 16` يمنحنا تقسيم الجداول حسب السنة (`Partitioning by Exercice`)، بحث فوري بالفهرسة الثلاثية `pg_trgm`، دقة مالية مطلقة `NUMERIC(19,2)`، وأمان عالي عبر `Row-Level Security (RLS)` وإضافة التدقيق `pgaudit`.
  - **فصل النواة المحاسبية:** خدمة Python FastAPI تتيح بناء المحركات المحاسبية الـ 9 بشكل معزول واختبارها آلياً بنسبة 100% دون الاعتماد على واجهة المستخدم.
  - **استقلالية الـ OCR:** محرك بايثون محلي (`PaddleOCR + TrOCR + LayoutLMv3`) يعمل 100% دون اتصال بالإنترنت.
- **العيوب (`Cons`):**
  - تعقيد حزمة التثبيت وإدارة تشغيل قاعدة بيانات PostgreSQL وخدمة بايثون محلياً على جهاز Windows. (يتم التخفيف منه عبر بناء حزمة تثبيت مدمجة `Integrated Windows Installer with one-command bootstrap`).

## 3. القرار النهائي والمبررات (Decision Outcome & Justification)

تم اعتماد **الخيار الثالث (`Tauri 2.x + Python FastAPI Modular Monolith + PostgreSQL 16 Partitioned + Local OCR Worker`)** كمعمارية أساسية ورسمية للمشروع بناءً على المبررات التالية:
1. **السرعة واستهلاك الذاكرة:** يلبي خيار Tauri متطلبات تشغيل النظام بكفاءة عالية على الحواسيب الضعيفة ويحقق زمن استجابة استعلامات أقل من `50ms` بفضل اتصال IPC السريع واستعلامات `SQLAlchemy Core` غير المحملة بعبء ORM.
2. **الأمان والامتثال المالي:** PostgreSQL يوفر البنية الأساسية المثلى لتنفيذ خطة الأمن المدمجة V3 (`Security Plan V3`) من خلال فحص التوازن على مستوى قاعدة البيانات (`Checks/Triggers`) وتقييد الصلاحيات بالـ `RLS` وحماية السجلات من المحو.
3. **الخصوصية والعمل دون إنترنت (`Offline-First & Local AI`):** فصل محرك الـ OCR في خدمة بايثون محلية يضمن أتمتة الإدخال مع الحفاظ التام على البيانات داخل مكتب المحاسب وعدم إرسال أي وثيقة للسحابة في الإصدار الافتراضي.

## 4. الآثار والتداعيات (Consequences)

### 4.1 الإيجابيات والمكاسب (`Positive Consequences`)
- تجربة مستخدم فورية فائقة السرعة تتفوق على البرمجيات السحابية وتحاكي سرعة الكيبورد في PC COMPTA.
- ضمان التوازن المالي الدائم وحماية الدفاتر المحاسبية من التلاعب أو الحذف المادي للقيود المعتمدة.
- إمكانية فتح وإدارة فترات وسنوات متعددة في الوقت نفسه بفضل استقلالية الـ `Partitions` في قاعدة البيانات.
- بنية مهيأة لتطوير واختبار النواة المحاسبية (`Domain & Core Engines`) بشكل مستقل عبر اختبارات الصمود والممتلكات (`Property-Based & Adversarial Tests`).

### 4.2 القيود والتحديات وكيفية معالجتها (`Trade-offs & Mitigations`)
- **تحدي التثبيت المحلي على Windows:** يتطلب تثبيت PostgreSQL وإدارة المعالجات المحلية.  
  *المعالجة:* بناء حزمة صامتة (`Silent Windows NSIS Installer`) تتولى إعداد وتشغيل قاعدة البيانات وإدارة التحديثات والنسخ الاحتياطي تلقائياً في الخلفية وبشكل مخفي عن المستخدم غير التقني.
- **استهلاك موارد الـ OCR المحلي:** قد يتطلب استخراج وثائق معقدة عبر `LayoutLMv3` وقتاً على المعالجات القديمة جداً.  
  *المعالجة:* استخدام نماذج مكممة ومطورة للخفة (`Quantized ONNX models / PaddleOCR baseline`) وتشغيل الاستخراج كعملية خلفية غير متزامنة (`Async Job Worker`) لا تعطل شاشة الإدخال السريع اليومي للمحاسب.

## 5. خطة التحقق والتراجع (Verification & Rollback Plan)

- **التحقق التقني (`Verification Strategy`):** يتم إثبات جدوى هذا القرار خلال المرحلة 01 (`Phase 01 PoCs & Benchmarks`) عبر بناء نماذج إثبات مفهوم قابلة للقياس وإعادة التكرار لتثبيت وتشغيل وإجراء استعلامات على ميزان مراجعة بـ 500,000 سطر، وقياس سرعة استجابة استخراج الفواتير بالـ OCR على أجهزة اختبار Windows فعلية.
- **التراجع المعماري (`Rollback Strategy`):** في حال إثبات عدم قدرة حاسوب مكتبي ضعيف على تشغيل خادم PostgreSQL محلي بكفاءة أو تعقيد التثبيت بما يتجاوز المعايير المعتمدة، يتم التبديل في الإصدار المنفرد (`Single-User Desktop Edition`) إلى قاعدة بيانات `DuckDB / SQLCipher with Embedded Analytical Partitioning` مع الحفاظ على نفس واجهة `FastAPI / SQLAlchemy Core` دون تغيير كود المجال أو واجهة المستخدم.
